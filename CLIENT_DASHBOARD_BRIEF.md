# ТЗ: Client Meta Ads Dashboard

## Цель проекта

Нужно сделать read-only дашборд Meta Ads для клиентов.

Идея: у каждого клиента есть своя ссылка на дашборд конкретного рекламного кабинета. Клиент открывает ссылку и видит понятную статистику по кабинету, кампаниям, группам объявлений и объявлениям.

Дашборд только отображает данные. Управление рекламой не нужно.

## Главный сценарий

Пример ссылки:

```text
https://your-dashboard.com/account/123456789
```

или:

```text
https://your-dashboard.com/account/act_123456789
```

Frontend берёт `account_id` из URL и запрашивает данные у backend/proxy.

Backend/Cloudflare Worker:

- берёт `META_ACCESS_TOKEN` из env
- проверяет, что кабинет есть в `ALLOWED_ACCOUNT_IDS`
- если кабинет разрешён, делает запросы к Meta Marketing API
- если кабинет не разрешён, возвращает `403`

Meta access token никогда не должен попадать во frontend.

## Cloudflare ENV / Secrets

Нужны переменные:

```env
META_ACCESS_TOKEN=...
META_API_VERSION=v21.0
ALLOWED_ACCOUNT_IDS=123456789,987654321,555555555
```

Правила:

- `META_ACCESS_TOKEN` хранится только в Worker env/secrets
- `ALLOWED_ACCOUNT_IDS` хранится в Worker env
- frontend не должен получать token
- frontend не должен напрямую ходить в Meta API

## Безопасность доступа

Worker должен нормализовать `account_id`.

Поддержать оба формата:

```text
123456789
act_123456789
```

Внутри Worker нужно привести к единому формату и проверить по `ALLOWED_ACCOUNT_IDS`.

Разрешены только:

- цифры
- `act_` + цифры

Любые другие строки отклонять.

Если кабинет не входит в `ALLOWED_ACCOUNT_IDS`, вернуть:

```text
403 Кабинет недоступен
```

## Layout

На странице должны быть:

- верхняя шапка кабинета
- выбор периода
- KPI-карточки
- таблица `Кампании и структура`

Интерфейс должен быть похож по ощущению на текущий Meta Ads dashboard: тёмный, аккуратный, рабочий, без маркетингового hero-блока.

## Статусы

Статусы только read-only.

Никаких тумблеров управления не нужно.

Показывать бейдж `Статус показа`.

Важно:

- статус не должен быть просто `ACTIVE/PAUSED` из кнопки управления, потому что управления нет
- статус должен подтягиваться из Meta API
- если кампания выключена, ad set и ads внутри неё не должны выглядеть как активные
- если ad set выключен, ads внутри него тоже не должны выглядеть активными

Цветовые группы:

- зелёный: активно
- синий: обработка / проверка
- серый: выключено / завершено / неактивно

## Креативы

У объявления должна быть кнопка `Креатив`.

По клику открывается модалка.

В модалке:

- слева сам креатив
- справа текст объявления
- справа заголовок
- справа ссылка

Требования:

- для image ads пытаться тянуть оригинал, не thumbnail
- для video ads пытаться тянуть `video source`
- если оригинал недоступен, использовать fallback preview
- если Meta не вернула креатив, показать аккуратное пустое состояние

## Валюта

- KPI-карточек
- таблицы кампаний
- таблицы ad set
- таблицы ads
- стоимости лида
- стоимости покупки
- CPC
- CPM
- расхода
- ценности покупок

## Worker API

Примерные endpoint-ы:

```text
GET /api/account/:accountId
GET /api/account/:accountId/summary?since=...&until=...
GET /api/account/:accountId/campaigns?since=...&until=...
GET /api/account/:accountId/campaign-tree/:campaignId?since=...&until=...
GET /api/account/:accountId/ad-preview/:adId
```

Все endpoint-ы должны:

- нормализовать `accountId`
- проверять его через `ALLOWED_ACCOUNT_IDS`
- использовать `META_ACCESS_TOKEN` из env
- не отдавать token на frontend
- возвращать понятную ошибку, если Meta API вернула ошибку

## Данные из Meta API

Нужно получать:

- account info
- account currency
- account name
- account-level insights
- campaign-level insights
- adset-level insights
- ad-level insights
- actions
- action_values
- cost_per_action_type
- campaign/adset/ad statuses
- даты завершения
- creative preview/media

## Метрики и формулы

Стоимость лида:

```text
spend / leads
```

Если `leads = 0`, показывать `—` или `0`, но не ломать UI.

Стоимость покупки:

```text
spend / purchases
```

Если `purchases = 0`, показывать `—` или `0`.

ROAS:

```text
purchase_value / spend
```

Если `spend = 0`, показывать `—` или `0`.

## Производительность

Важно не делать слишком тяжёлые запросы.

Правила:

- не тянуть всю структуру сразу
- ad set и ads загружать лениво при раскрытии кампании
- creative/media загружать только при клике на `Креатив`
- большие запросы разбивать на страницы
- не запрашивать лишние поля

## Обработка ошибок

UI не должен падать.

Показывать понятные ошибки:

- кабинет недоступен
- кабинет не найден
- token истёк
- token невалиден
- Meta API rate limit
- нет данных за период
- Meta не вернула часть полей

Если данных нет, показывать:

```text
—
```

или:

```text
Нет данных
```

## LocalStorage

Хранить в `localStorage`:

- видимые KPI-карточки
- порядок KPI-карточек
- выбранные колонки таблицы
- ширины столбцов
- фильтр `Только с показами`
- фильтр `Только активные`

Можно хранить настройки глобально или с привязкой к `account_id`, чтобы у разных клиентских ссылок были свои настройки.

## Критерии готовности

Проект готов, если:

- можно открыть страницу `/account/:accountId`
- `accountId` берётся из URL
- Worker проверяет `accountId` через `ALLOWED_ACCOUNT_IDS`
- token остаётся только в Cloudflare Worker env
- клиент не видит token
- отображаются KPI-карточки
- работает выбор периода
- работает таблица campaigns / ad sets / ads
- работают поиск и фильтры
- открывается модалка креатива
- все денежные значения отображаются в валюте кабинета
- нет функций управления рекламой
- нет графиков
- нет воронки
- нет мультиаккаунтного интерфейса
